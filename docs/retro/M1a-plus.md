> M1a-terrain-world-proposal.md 的 T0/T1 短切片）；只做表现与证据，

## BLEND-01（2026-10-10）

- **做对的部分**：权重先拆成纯逻辑合同（`hex_terrain_blend.gd`）再进 mesh——
  「两端纯色、中点 0.5、和恒 1」全部 headless 可锚，不靠目检断言；blend 与
  fallback 走同一发射路径，几何/face 表/碰撞逐位一致的等价性测试先于目检落地，
  「表现层切片不动拾取合同」从纪律变成了断言。
- **踩的坑（两条，均已进测试锚）**：① Godot 标准 `ARRAY_COLOR` 是 8-bit 归一化
  存储，浮点精确比较必失败——纯色语义锚合同层、mesh 层用 1/255 容差；②
  `Vector2` 分量为 float32，权重和有 ~1e-8 舍入——密集采样断言与
  `is_valid_weights` 统一 1e-6 窗口。另：用例内 SCRIPT ERROR 会让 run_one 的
  `_init` 中止、进程不退、被 N-3 超时拦截（门禁行为正确，排障时先看转发行）。
- **取舍登记**：中点不落 mesh 顶点（改面数 = 动 face 表/碰撞，实现要点 5 不许），
  由端点纯色 + 仿射线性行插值实现，测试用 blend_color 链路锚等价；blend surface
  保持按地形分组（换取 faces 序与 fallback 逐位一致），省 draw call 的单 surface
  重组留给真正需要时翻案。
- **五个追问**：换美术者能否只换 .tres 就换两风格观感？——能（palette 从同一
  材质库提取）。规则层是否感知权重？——否（MapData/寻路/战斗零改动）。旧渲染
  能否一键退回？——能（render_style=SLOTS / build_map 原入口）。下张卡（BLEND-02
  三格角 + 跨 chunk）复用什么？——端点=所在格纯色的角落规则已锚，只需加三方
  权重与 shared position 合同。纹理版（Should）何时进？——本卡未做，等 BLEND-03
  的 style 对账先行。

## BLEND-02（2026-10-10）

- **做对的部分**：三格权重完全复用 BLEND-01 的「顶点纯色 + 面内插值」模式——
  角面顶点本就是合同单位权重锚点，把合同钉成 `corner_weights/blend_color3` 后
  mesh 侧零行为变化即通过全部新锚（「表现层切片不动 face 表/碰撞」再次兑现成
  断言而非纪律）；跨 chunk 一致性用「同图三种划分（单块/行切/每格一块）角面
  位置+顶点色逐位一致」锚死，比单点对账强——每格一 chunk（25 块）顺带把所有
  跨块路径塞进了无裂缝流形测试；两色角按「地形聚合权重」显式退化对账边带合同，
  「最多三种」的最大与常见两态都有锚。
- **踩的坑（两条，均已进测试锚；均为 BLEND-01 教训的变体而非新问题）**：①
  Vector3 权重分量是 float32，1/3 不可精确表示——重心均值断言的 1e-9 精确窗口
  失败（BLEND-01 中点 1e-9 能过是因为 0.5 可精确表示），统一 1e-6；② `1−u−v`
  在 u+v=1 边界有 ≤1 ulp 负舍入（−2.8e-17），严格非负检查会拒掉数学上合法的
  边界权重——`is_valid_weights3` 非负项带 −eps 浮点零点窗口（真负权重 ≫ eps
  照拒）。另：mesh float32 顶点与 float64 公式是两条浮点路径，「p2−p1 == bridge」
  式的差值断言会假红——期望值必须按 builder 同路径拼装再逐位比（同路径逐位、
  跨路径 1e-5 的既有口径）。
- **取舍登记**：角面不细分（不加重心/边中点顶点）——改面数 = 动 face 表/碰撞
  合同，表现层切片不许；三方混合全靠三角内插值，重心等价用 blend_color3 链路
  锚。角面顶点色规则沿用 BLEND-01 已锚的发射序 (p1,p3,p2) → (owner, N(k−1),
  N(k))，本卡只补合同与跨块/退化/拾取锚，不重锚已有事实。
- **五个追问**：三方权重在 GPU 插值下还「和恒 1」吗？——是（三顶点纯色仿射
  插值 = 权重线性组合，重心等价链路锚定）。跨 chunk 角面谁生成？——三格稳定
  ID 最小者的 chunk（T4 归属不动，测试按划分核发生成块）。两色角（草-草-泥）
  要特殊处理吗？——不要，按地形聚合权重自动退化为边带合同（测试锚）。高程差
  的三格角（非等高）怎么办？——几何/UV 已由 T4/T8 覆盖，权重只叠顶点色，本卡
  全平高程验证材质面（高程混合掺变量属后续卡）。下张卡（BLEND-03 换 style 对账）
  复用什么？——mesh↔mesh 跨划分逐位精确 + 8-bit 容差两套比较口径，直接搬。

## BLEND-03（2026-10-10）

- **做对的部分**：style 收成纯配置资源（TerrainStyle .tres，T8 先例）而不是
  散落布尔开关——「换纹理不改主线」从两份沙盒脚本的手工 dispatch 变成
  `MapView.build_with_style` 一个入口、检查器换 .tres 即换装；不变量测试把
  验收原文逐条翻成断言（summary 逐字节 / ARRAY_INDEX 与 face 表逐位 /
  连通性整体一致 / 材质实例确不同），且 Given 守卫用同 seed 双实例走真实生成
  管线——「同一张图」不靠共享同一个 MapData 实例伪造。SLOTS/blend 两条路线的
  等价性 BLEND-01 已锚过一次，本卡把同一不变量**穿过 style 解析层**再锚一遍
  （路径 = inputs_for → builder 双入口），builder 与 fallback 零改动。
- **踩的坑（一条，未进测试但登记）**：`--script` 临时冒烟脚本里
  `var want := 1 if cond else expr` 三元推断失败（Parse Error）——引擎把
  inference_on_variant 当错误，临时脚本也要显式类型；顺带发现 shell 管道尾的
  `$?` 不是 godot 退出码，门禁/scene_check 的退出码必须脱离管道单独取
  （复核时已全部重取真实 exit code）。
- **取舍登记**：①解析预检只看图内被用到的地形 id——库里多余的未用槽（哪怕
  ShaderMaterial）不挡图，色板逐槽提取而非全表提（口径同 builder「先全图
  预检后建」）；②「材质效果不同」headless 只锚到材质实例 + 顶点色通道
  （BLEND 跨地形边带端点异色 / SLOTS 无 COLOR），像素级差异归 GATE-02 渲染
  证据，不在单测里伪造像素 oracle；③ MapView 分发逻辑不进 tests/（view 层
  可删纪律），分发等价性 = 沙盒冒烟 + 两入口既有测试；④ mods 保持空显式断言
  ——「不新增规则语义」从纪律变成检查。
- **五个追问**：换美术者动几个文件？——0 个代码文件：换 style .tres 或改
  材质库 .tres（检查器）。换 style 会动碰撞吗？——不会（碰撞汤逐位一致锚定，
  提案「材质、贴图和纯装饰变化原则上不重建碰撞」兑现）。SLOTS 为什么留？——
  一键退回旧渲染 + 对照档（GATE 纪律「每次迭代都能回到旧渲染」）。纹理版
  （Should）还差什么？——载体已就位：材质库换贴图槽 / blend_material 换 shader，
  合同不动。style 会不会渗进规则层？——MapData/连通性/寻路不 import 它；
  tests 锚 summary/to_dict/mods 三面零变化。

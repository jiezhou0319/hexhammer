# 风格化地图生成方案：群山、平原与派系适配

本版依据邮件中上一版方案摘要，以及本轮明确的“成片群山、偶尔孤峰、大片区域有不同主导地貌”方向整理。它是一份可独立阅读的整合修订稿，不是对未取得的上一版完整附件逐行修改。本轮只调整设计文档，不修改源码，也不代表已经验证生成效果或性能。

## 问题与设计结论

地图不应处处都是同等重要的小起伏，而应有可辨认的大片群山、宽阔平原、盆地和过渡带。这样的地图既能形成清晰构图，也能为未来派系提供不同的活动与聚落基础：例如矮人偏好群山内部的山谷和盆地，人类偏好平原与河谷。

**采用“区域主导地貌 + 局部变化 + 少量地标”的分层生成方式。** 用户提出的限制不是需要消除的问题，而是地图风格的设计约束；应先限制大尺度结构，再允许小尺度细节自由变化。

具体含义如下：

- **区域主导地貌**：一大片区域整体偏群山，另一大片区域整体偏平原，但不是每个格子都相同。
- **局部变化**：群山中保留谷地、山口和盆地；平原中允许缓丘、河谷以及少量孤峰。
- **地标例外**：孤峰作为明确的构图对象生成，而不是由高频噪声随机冒出一堆尖点。
- **派系适配**：先生成有特色、可使用的地貌，再为派系筛选适合的落点；默认不预先把区域永久划给某个派系。

## 目标与非目标

### 目标

- **宏观可读性**：关闭派系标记和装饰后，仍能看出至少两种大片主导地貌，不能只靠颜色区分。
- **局部可用性**：群山不仅有山峰，也有满足最低可用面积与通达要求的谷地、盆地和山口。
- **派系差异基础**：同一张地图能提供偏群山与偏平原的不同候选落点，后续派系系统可直接读取。
- **生成稳定性**：同主 seed、同生成器版本、同配置产生一致的权威地图数据；修改派系显示配置不应改变基础地形。
- **可验证性**：每个区域输出地貌占比、连通分量、可用面积与违规项，用检查报告而不是观感替代全部验收。

### 非目标

- **真实地质模拟**：本阶段优先满足构图与玩法，不追求完整地质演化。
- **整块单一地形**：不做“山地区域全是山、平原区域全是平格”的硬切分。
- **永久派系领土**：不把“矮人偏山、人类偏平原”升级成独占或不能跨区活动的规则。
- **完整派系玩法**：暂不设计派系数值、兵种、经济与战争规则。
- **全面重写**：本阶段不同时迁移全部水系、道路、存档和表现模块；分阶段验证后再接入。

## 用户体验

- **玩家**：希望从远景就能辨认山地世界与平原世界，近景又能发现山口、谷地和孤峰等值得探索的位置。
- **未来的派系玩家**：希望不同派系的初始地形体现特色，但不会因山地完全封闭、平原过度破碎而失去发展空间。
- **地图作者**：希望控制的是区域大小、山系走向、平原完整度和孤峰稀疏度，而不是逐格修补随机噪声。

## 生成主线

新版主线为：

```text
主 seed 与生成身份
  → 世界构图与宏观地貌分区
  → 区域内部骨架：山系、宽谷、盆地、平原、少量孤峰
  → 连续高度与区域过渡
  → 选择性侵蚀外观
  → 六边形玩法投影与可用性检查
  → 合法排水、河湖
  → 派系适宜度与候选落点
  → 聚落、道路、桥与关隘
  → 风格化表现与最终验收
```

分区和骨架是上游约束，噪声与侵蚀是下游细化。不得让后面的细节阶段重新把完整平原切碎，或把主山系打散成互不关联的尖峰。

### 宏观分区

先生成少量空间连贯的地貌区域，并记录区域之间的邻接关系。区域数随地图尺寸和最小可用区域面积确定，不能在小地图上机械套用大地图数量。

建议首期仅实现两种主导类型及其过渡：

- **群山主导区**：通过有方向的主山系、支脉和宽谷组织结构，而不是独立抬高大量格子。
- **平原主导区**：通过大片低起伏地形构成主体，少量缓丘、河谷和孤峰构成变化。
- **过渡带**：采用山前丘陵、宽谷出口、缓坡或盆地边缘连接两区，避免分区边界呈现拼图式断崖。

海域开口、高原、赤岩台地与岛链等可以后续扩展，但不列入本阶段必做内容。

### 群山与孤峰的不同职责

群山是区域结构，孤峰是局部地标。二者应使用不同的对象和约束，不能只通过一个噪声阈值控制。

- **群山对象**：主山系走向、宽度、支脉、峰簇、山口和谷地组成一个整体。主山系需要在六边形投影后仍保持可识别的连贯性。
- **孤峰对象**：显式选择中心、影响半径、峰高与形状，限制与其他孤峰、主山系、起始落点的距离。
- **峰簇与孤峰识别**：主山系内部的突出峰不自动计作孤峰；应按对象归属和空间隔离程度判定。
- **平原中的孤峰**：允许出现，但设置影响面积预算，不能让孤峰及其山脚占据过多平原。

孤峰数量优先由有效平原面积、最小间距和构图位置决定。小地图可以没有孤峰，不要求每个区域都配置一座。

### 连续高度与过渡

区域边界用连续权重场表达，不把区域编号直接当成高度阶跃。可用以下设计表达式组织实现：

```text
最终候选高度 =
  基础大陆高度
  + 各区域权重 × 对应地貌骨架
  + 振幅受限的局部细节
  + 孤峰地标
```

权重需要归一化，但单纯混合高度并不足以保证好看的山前过渡。主山系还需要设置终止、降低或延伸规则，避免边界出现被切断的山脊；群山向平原的过渡也可以通过宽谷出口组织。

平原的细节振幅受坡度与起伏预算限制。群山的细节强度可更高，但谷底、山口与候选可用区需要保护，避免细节覆盖骨架。

### 选择性侵蚀

保留上一版“先连续地形，后选择性侵蚀，最后格级投影”的方向。侵蚀在本阶段只承担外观细化，不直接提供权威游戏河流。

- **群山坡面**：允许更明显的沟壑和山脊细化。
- **宽谷与盆地**：限制侵蚀造成的割裂，维护可用面积。
- **平原**：弱侵蚀或关闭侵蚀，优先保留大片连贯性。
- **过渡带与海岸**：分别控制细节强度，保护整体轮廓。

侵蚀后重新检查起伏、坡度和连通性。若破坏区域约束，应按确定性规则减弱局部侵蚀或回退局部结果，不用换整张地图 seed 掩盖问题。

## 区域限制：硬约束与软目标

“一大块区域以一种风格为主”不等于严格禁止其他地形。建议把约束分为以下两类：

| 对象 | 硬约束 | 软目标 |
|---|---|---|
| 群山主导区 | 达到最小区域面积；保留必要可用谷地及对外通路；区域数据合法 | 主山系明确；峰簇连贯；宽谷有层次 |
| 平原主导区 | 起伏预算不过限；最大可用连通片达到配置要求；孤峰影响面积不过限 | 大片开阔；局部缓丘；少量地标 |
| 过渡带 | 不出现由区域编号导致的高度断缝；通路满足设定 | 山前丘陵、缓坡与谷口自然组织 |
| 孤峰 | 最小间距、影响面积预算、避让规则全部满足 | 位置有构图价值，形态与主山系不同 |
| 派系候选落点 | 满足面积、通达、水与资源规则中的必需项 | 尽可能体现该派系地貌偏好 |

地貌占比应在区域核心范围统计，过渡带单独统计；必须明确分类阈值和分母，避免用整张地图占比掩盖某个区域失败。高度、坡度与区域标签分别记录，“标为群山”本身不能算生成了群山。

### 首期调参起点

以下数值是建议的实验初值，不是已验证结果，也不是最终平衡承诺：

- **群山区域核心**：山地与丘陵合计占比可从 60%～80% 起调；同时独立保证谷地、盆地的最小可用面积。
- **平原区域核心**：平原与缓丘合计占比可从 70%～90% 起调；主要通行空间必须形成配置要求的大片连通区域。
- **孤峰预算**：孤峰及其山脚总影响面积可先不超过有效平原面积的 5%，并设置相对于峰体半径的最小间距。
- **过渡宽度**：可从相邻较小区域特征尺寸的 10%～20% 起调，并设置按六边形格数衡量的下限。

这些范围不能脱离地图尺度直接使用。特别是“山地与丘陵合计占比”不足以保证群山风格，因此仍需检查主山系数量、范围和峰簇结构。

## 派系适配

### 默认关系

默认采用“地形先成形，派系后选址”。上游生成器保证存在多种有特色、可使用的区域，下游派系系统根据偏好筛选位置；派系名单变化不应直接改变同一配置下的基础高度。

偏好只表示适合度，不表示整个区域的归属：

- **矮人**：倾向群山内部的谷地、盆地、山口附近和资源合适的位置，而不是直接把城市放在最高或最陡的山峰上。
- **人类**：倾向连贯平原、宽河谷和道路扩展条件好的位置，而不是只比较海拔是否最低。
- **后续派系**：通过适宜度配置扩展，不把派系名称写进基础地貌生成代码。

### 两阶段选址

先执行硬筛选，再评分，避免高“风格分”覆盖不可用条件：

```text
候选集合 = 面积、通达与其他必需条件全部合格的位置
适宜度评分 = 地貌偏好 + 可扩展空间 + 水资源 + 资源条件 + 战略位置
最终落点 = 候选集合内评分与间距规则共同决定的结果
```

如果未来需要保证某些派系一定能开局，应显式启用“开局保证模式”。该模式在构图阶段预留地貌能力需求，在最终阶段检查候选数量；它属于生成配置的一部分，必须进入配置哈希，不能悄悄修改默认地形。

### 失败与回退

- **默认模式**：没有合格候选时返回明确失败原因，或按已配置的规则放宽软偏好；不能放宽不可通达等硬条件后仍称为合格。
- **开局保证模式**：允许有界次数的局部修复，例如拓宽谷地、补山口或调整平原碎片，并重跑受影响的水系和通达检查。
- **修复耗尽**：返回失败报告或显式生成失败，不无限重试、不悄悄换主 seed。

最小可用面积、候选数量、通达目标和资源需求目前均待后续玩法确认。本阶段提供配置入口，不杜撰最终平衡数值。

## 水系、聚落与道路

保持上一版独立合法水系的方向：从最终权威地形建立排水关系，再选择主河、湖泊与出口。若使用格边河，应在角点／格边图上求解相应拓扑，不能只把连续高度上的沟槽贴到棋盘上。

- **群山水系**：利用谷地与盆地组织汇流；任何填洼、开槽或高度修复，都需复查山口、谷地与区域约束。
- **平原水系**：允许主河通过，但限制无关细沟造成过度碎片化；湖盆和外流出口按水系规则处理。
- **聚落**：结合派系偏好与可用空间选址，不以区域标签直接替代选址检查。
- **道路**：连接实际聚落与通路，利用山口、谷地和合法桥址，不因有了新地形算法而省略道路验收。

原有路网误判、桥拾取与水面遮挡仍是独立修复项。地形重构不会自动解决这些问题，也不能把它们混入地貌效果对比后忽略。

## 数据与确定性合同

建议数据结构如下，名称可与现有工程适配：

```text
WorldGenerationIdentity
  world_seed
  generator_version
  config_hash

TerrainRegion
  stable_id
  dominant_landform
  core_mask / blend_weights
  adjacency
  constraints

TerrainSkeleton
  mountain_ranges
  ridge_branches
  valleys / basins / passes
  isolated_peaks

TerrainFacts
  continuous_height
  hex_height / slope / landform
  playable_components
  drainage / rivers / lakes

FactionSuitability
  profile_id
  candidate_sites
  rejection_reasons

GenerationReport
  stage_checksums
  region_metrics
  constraint_violations
  repairs_applied
  final_status
```

玩家仍只输入一个 `world_seed`。内部通过稳定的派生规则隔离 `layout`、`region`、`mountain`、`isolated_peak`、`erosion`、`hydrology`、`settlement` 与 `road` 随机通道，避免增加一个装饰对象就改变整张地形或路网。

随机通道的隔离不保证上游改动对下游完全没有影响。例如侵蚀改变权威高度后，合法水系可以随之改变；承诺应限定为“未改变依赖输入的阶段不会因无关随机调用而变化”。

存档保存生成身份和权威世界快照。CPU 负责玩法事实，GPU 主要负责表现；跨硬件一致性是需要验证的目标，不在未测试前承诺已经实现。

## 实施分期与需求优先级

### 构图原型

**P0：先验证群山和平原是否形成不同的区域结构。**

- **宏观区域**：生成群山区、平原区、核心范围与过渡权重。
- **地貌骨架**：生成有走向的山系、宽谷与少量孤峰，保留平原完整度。
- **连续高度**：将骨架转为高度，在连续层完成混合，再做六边形投影。
- **调试预览**：提供区域、骨架、高度、坡度、可用连通片五种视图。
- **固定对照**：用同种子与同相机比较“旧版／分区骨架版／分区骨架＋侵蚀版”。

这一阶段不要求正式派系系统，只在预览中标出“山地偏好候选”和“平原偏好候选”，并说明候选采用了哪些临时规则。

### 玩法合法性

**P0（接入正式地图前）：保证投影后的地图确实可用。**

- **合法水系**：依赖最终权威地形与投影规则。
- **区域验收**：检查核心占比、最大可用连通片、谷地和对外通路。
- **可控修复**：记录失败原因与确定性修复过程。
- **一致性**：实际几何变化同步碰撞、拾取和通行，不能只改 shader 外观。

### 派系与内容接入

**P1：地貌通过验收后接入适宜度、聚落与道路。**

- **偏好配置**：建立与派系名称解耦的地形适宜度配置。
- **候选选址**：先硬筛选，后评分与间距控制。
- **开局保证**：仅在明确需要时实现，并单独验收。
- **表现扩展**：完成基础结构后，再添加建筑、植被与材质强化风格。

赤岩台地、岛链与山湾等新模板属于 P2，不阻塞首期群山和平原原型。

## 验收与评估

建议首期使用固定的 20 个 seed，覆盖小、中、大三档地图尺寸。该样本用于开发回归，不代表已经完成验证，也不替代后续压力测试。

| 场景 | Given / When / Then 验收条件 |
|---|---|
| 区域主导性 | 给定区域核心与分类阈值，生成后，各区域统计满足当前配置中的地貌占比范围，并输出不合格区域编号。 |
| 群山结构 | 给定要求的主山系数量和范围，完成投影后，山系对应的格级范围、峰簇与谷地仍满足配置检查，不能只剩散峰。 |
| 平原完整性 | 给定最低可用连通面积和起伏预算，完成侵蚀与投影后，两项均满足，孤峰影响面积不超预算。 |
| 孤峰稀疏性 | 给定影响半径、最小间距及避让规则，生成后逐峰检查，违规数为零；可因地图过小生成零座。 |
| 边界过渡 | 给定区域边界与允许坡度规则，混合后无分区编号导致的高度断缝；对指定过渡带和通路逐段检查。 |
| 山地可用性 | 给定最小谷地面积、山口与对外通达要求，生成后可用连通片及其连接满足要求，否则明确失败。 |
| 派系候选 | 给定偏好配置与必需条件，筛选后所有合格候选均满足硬条件；没有候选时输出原因，不能返回伪合格位置。 |
| 水系合法性 | 给定最终排水图，检查无非法循环，河流符合下游关系，终点符合出口或湖盆规则；视觉沟槽不能充当验收结果。 |
| 确定性 | 给定相同生成身份，在支持环境内重复生成，权威地图数据与阶段校验值一致。 |
| 随机隔离 | 仅改变不参与权威地形的装饰配置后，基础地形和水系校验值不变；只改派系显示时同样成立。 |

**结构风格单独做人工评审。** 关闭颜色、派系和装饰，使用统一灰度与相机观察各 seed，检查是否能辨认群山、宽谷、平原和孤峰；记录未通过的 seed 与具体问题，不能用颜色漂亮代替地形结构成立。

性能指标在原型基线上测量生成时间、峰值内存和各阶段开销，再制定预算。本版不预设未经测量的毫秒级承诺。

## 尚待确认

- **地图尺度，项目负责人，接入前阻塞**：不同尺寸的格数与最低有效区域大小，需要结合现有工程确认。
- **地貌分类，地形实现负责人，自动验收前阻塞**：坡度、起伏和可用地块的分类阈值需要统一。
- **派系开局规则，玩法负责人，派系接入前阻塞**：是否保证每局都有矮人与人类，以及候选面积、数量、间距和资源需求。
- **孤峰风格，美术与玩法负责人，非阻塞**：首期可只做少量圆锥／岩峰轮廓，后续再决定是否关联遗迹、资源或战略地标。

## 本轮修订摘要

上一版强调“有构图的大地形”，本版把它具体化为“先定义大片主导地貌，再组织区域内部结构”。群山不再等于全图高频起伏，孤峰不再是随机噪声副产物，派系特色也不再只靠后期换颜色或贴建筑。

首期应证明三件事：群山是成体系的，平原是连贯的，孤峰是少而有意义的。这个基础成立之后，再用地形适宜度承接派系与聚落，既保留风格化限制，也避免提前把世界锁成死板的派系分区。

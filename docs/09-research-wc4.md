## 1. 战斗数学（主要指向 docs/07）

### 1.1 WC4 伤害公式还原〔A〕

`wc4-tools:analysis/report_skill_damage_code.md` §0/§2（so 0x3c6e98 → 0x3c4a28，
7 处调用点一致）：

```
最终伤害 = int( 当前攻击力 × 防御减伤 × 技能系数 )
当前攻击力 = 当前兵力(HP) × 兵种强度/100 × 编队系数 + 固定附加值
           + 将领星级攻击 + 百分比加成（掉血后线性缩放）
防御减伤  = × 1000 / (16 × 防御力 + 1000)        ← 收益递减，永不为 0
技能系数  = 从 1.0 起，每个生效技能 ×(100+效果)/100 连乘；特殊克制 ×0.55 / ×0.40
暴击      = rand(1,100) ≤ 暴击率 → ×倍率（1.2~2.0 按技能等级）
```

**→ hexhammer**：与 docs/07 §1 的 v5 公式（`ATK²/(ATK+DEF)` 比值模型 + 乘法修正链）
结构同型——**基础伤害单调有界、防御饱和、修正乘区连乘、概率层独立**。一个运营 8 年+
的商业 SLG 与我们的 v5 在骨架上一致，是比值模型选型的旁证（07 §1 公式选型史可补此参照）。

### 1.2 ⚠ 核心警示：加法百分比聚合会算出负伤害（→ docs/07 §1 增减伤层）

**WC4 事实**：穿甲/防护是**加法百分比聚合**——勋章、技能、特性提供的穿防百分比
直接相加（如 55% + 187% = 242%），聚合发生在勋章穿防聚合函数（1.28.3 so 0x380240，
1.30.2 重定位 0x384f18，函数语义已逐指令验证等价，〔A〕`wc4-tools:analysis/v1302_report/E_platform.md`
§3.5/§7.2；libwcx 修改框架的钩子名 `wc_h_def_pen` 亦印证此管道，同报告 §3.3）。
后果：**总穿防 > 100% 且火力 D ≥ 63 时出现负伤害**〔B——WC4 项目方给定的已验证事实〕。
这是加法百分比体系的经典陷阱：多来源减益线性求和，迟早叠过 −100%。

**→ hexhammer（直接命中 docs/07 §1）**：v5 公式的修正层写的是

```
× (1 + 增伤% − 减伤%)
```

**同一类加法聚合**。docs/07 §1 只对基础伤害声明"恒正，无保底条款"——比值模型的
基础项确实恒正，但修正层没有下限：减伤来源叠到 >100% 时最终伤害为负，与 WC4 同病。
当前已设计的减伤源（docs/08 §2：盾墙 −15%×最多 2 邻 = −30%、防守姿态等）离 −100%
尚远，但 07 §1 明言概率/修正空间"留给**装备与主城特化**体系做成长钩子"——正是
WC4 炸掉的那条路（勋章=装备位，叠加来源最多）。

候选处置（**均待拍板，本文不改 07 v5 一个字**）：
1. 给该层加钳制（如净增减伤 ∈ [−75%, +100%]，或总乘 ≥ 0.25）——WC4 的移动力管道
   就是在**消费端**钳 0（见 §1.7），证明"钳在最后一处消费点"是可行且够用的；
2. 或把多来源减伤改连乘（每源 ×(1−x%)），天然恒正；
3. 最低成本：在 `tools/damage_calc.html` / `tools/combat_sim.gd` 加一行
   "极端修正堆叠"敏感性测试（把全部已知减伤源同时拉满），纳入 07 §4 的校准工具箱，
   每次 08 加新机制时跑一次。

### 1.3 防御走饱和曲线：加法输入的安全前提（→ docs/07 §1 公式本体）

**WC4 事实**：防御力本身是**加法聚合**（army.Defence + 将领星级防御 + 工事等增益，
〔A〕report_skill_damage_code §2.5），但被 `×1000/(16×Def+1000)` 消费：Def 25/50/100/200
→ 伤害保留 71.4%/55.6%/38.5%/23.8%——翻倍防御只多削一小块，永不到 0。

**→ hexhammer**：v5 的 `ATK²/(ATK+DEF)` 同理（DEF 只进分母、边际递减）。设计通则
由此提炼：**加法聚合不是原罪，把加法结果线性地喂进伤害才是**。本项目应守住两条：
① DEF/属性类输入保持加法（直观、可堆叠）但必须进饱和曲线（已满足）；
② 百分比修正若保持加法，必须配钳制（§1.2，未满足，待拍板）。

### 1.4 输出随血量衰减：线性 vs √（→ docs/07 §1 血量修正）

**WC4 事实**：攻击力 = 当前兵力 × 兵种强度/100，掉血后 `cur = min(cur×newMax/oldMax,
newMax)`——**线性**衰减（〔A〕report_skill_damage_code §2.3；Advance Wars 同思想，
见 08 §1.5）。

**→ hexhammer**：v5 用 `√(当前HP/满血HP)` 只作用于攻击者。对比结论：线性衰减让
残血单位输出崩塌→战斗内滚雪球（强者愈强、追击收割快）；√ 衰减让残血单位保留多数
输出，支撑 docs/06 §4"势均力敌打 3~6 个游戏回合"的拉锯节奏。WC4 选线性与其
"PvE 速推"的产品形态自洽；本项目拍板"棋子不会被一回合秒杀、拉锯有窗口"
（00 支柱 2），**√ 是与该支柱一致的取法，无需改动**。07 §1 已记录"血量修正挂错
目标"的实现 bug 史——WC4 的 battle 结构里攻防/血量修正各挂各的偏移（+0xd8/+0xdc），
同样提示：修正对象的归属要在实现层显式命名。

### 1.5 乘区连乘的预算管理：逐格百分比的教训（→ docs/07 §3 修正层数值）

**WC4 事实**：技能系数从 1.0 起连乘，乘区来源包括技能/兵种特性/战场 buff 三类
（〔A〕report_skill_damage_code §2.2）。其中"每移动 1 格伤害 +N%"（洞察先机，
buff 1221~1226）在 1.30.2 被**全等级 nerf**：3/4/5/6/7/8% → 1/2/3/4/5/6%（上限 50%
不变），波及曼施坦因/拿破仑等一大批持有者（〔A〕`wc4-tools:analysis/v1302_report/E_platform.md`
§8-1）。

**→ hexhammer**：① 逐格/逐段百分比与高机动单位相乘后强度失控，官方亲自示范了
"逐格值砍半 + 保留硬上限"的修法——本项目骑弓"帕提亚回射"是**定额 +20%**（移动 ≥2 格，
docs/08 §2），不随格数放大，是对的形态，保持；② 连乘乘区要做**总预算审计**：
docs/07 §3 的修正层设计稿（克制 ×1.75、冲锋 ×2、守减伤 40%、围攻 ×1.25）彼此已是
乘法叠加，再加装备/特化百分比前，先用 07 §4 计算台扫"全修正拉满"的组合值——
建议把"乘区总预算表"列为 08 兵种定稿时的检查项（待拍板）。

### 1.6 克制=固定倍率、穿甲=百分比无视（→ docs/07 §3 / docs/08 §2 槽位表）

**WC4 事实**：硬克制走**固定倍率**：Type 41 技能对步兵 ×0.55、对火炮 ×0.40
（〔A〕report_skill_damage_code §2.2）；穿甲走**百分比无视防御**：1.30.2 新技能
91/92（王牌步兵/海军）无视敌方 15~90% 防御，且**顶级也只到 90%、从不给 100%**
（〔A〕`wc4-tools:analysis/v1302_report/A_generals.md` §2.1）。

**→ hexhammer**：① 本项目"克制 ×1.75 / 冲锋 ×2"（07 §3）与 WC4 的 0.55/0.40 同为
固定倍率槽——固定倍率不参与堆叠数学、一句话说得清，两边殊途同归，维持；
② 法师"秘术穿甲 = 按 DEF 0 结算"（08 §2）是 100% 无视，比 WC4 任何可学穿甲都极端。
它在本项目安全的前提是法师 ATK 定值 84（全场下游）+ 体质最脆（08 §3.6）——
**全额穿甲必须绑定低基础输出**，否则就是"无视防御的弓箭手"。将来若加"穿甲装备"，
建议走 WC4 式百分比档位（30/60/90% 三档之类），别再开第二个全额穿甲位（待拍板）。

### 1.7 负值字段与消费端钳制（→ docs/07 §1；docs/08 机制参数）

**WC4 事实**：我方"驻城勋章"利用 SkillEffect=-30（负移动力）：引擎**有符号读入**、
详情 UI 渲染红色"部队行动力-30"、移动力管道在消费点**钳 0**，摘下即恢复
（〔A〕`wc4-tools:analysis/guide_mod_v128.md` §2.8.1）。

**→ hexhammer**：负值修正是合法且好用的设计空间（减益装备/地形惩罚），但 WC4 的
顺序是"字段允许负 → **消费端钳制**"。本项目的血量、移动力、士气管线都应明确
"谁负责钳下限"（一处、且只在一处），这是 §1.2 钳制建议的同一条原理。

### 1.8 AI 评估复用同一伤害函数（→ docs/07 §4 工具 / docs/02 规则层）

**WC4 事实**：伤害系数函数 0x3c4a28 的 7 个调用点里有一个是 **AI 评估**（0x3b11c4），
其余为预计伤害/实战结算（〔A〕report_skill_damage_code §2.1）——AI 与玩家共用同一套
伤害数学，无第二套公式。

**→ hexhammer**：印证既有架构方向（02 分层图"规则层纯函数、AI 只是换命令生产者"；
06 §8"AI 与玩家走同一套意图系统"；01 A4 Tessera 同结论）。WC4 的具体启示是：
**AI 的强度评估调用解算器本身**，而不是调"解算器的近似"——近似版 AI 会系统性
误判克制/穿甲价值。本项目做"AI 集火残血、识破包抄"（06 §8 战术深化）时，评估函数
直接 import 规则层纯函数即可，0 成本对齐。

## 2. 科技与成长链（指向 docs/06 §6 主城特化 / docs/08 §6-9 精锐档）

### 2.1 总量替换 + 显式链表

**WC4 事实**：科技链递进靠 UpgradeID 显式链接（链尾=0，无 Level 隐式回退）；
**链内数值是"当前等级总量"而非增量**——精锐步兵 475 血 = 325 基础 + T2 Lv7 总量 150；
追加顶+1 的新科技必须继承前级全部数值再加净增（〔A〕guide_mod_v128 §2.7，
三次逆向定论）。

**→ hexhammer**：docs/06 待细化 #5 的"精锐档=四维×1.2"是**模板乘法**，天然无此问题；
但 §6"主城特化解锁高级兵"、将领等级成长（待细化 #6）一旦做成"链式解锁"，就会遇到
同一选择。结论：**成长数值存总量、链关系存显式引用（前一档 Id），不要存增量**——
增量制在"中途插档/重排"时会全链错位（WC4 同因）。

### 2.2 存量兼容：插队倒退与"留壳"

**WC4 事实**：在链中间插档且数值低于旧顶级，会让**已研究玩家属性倒退**（实测步血
Lv8：官方顶级 300 vs 前级基准 190 → −110）；已研究过的链节点**不能删**——删除会使
等级查询越界返回 null，连官方加成都归零，只能留"零净增壳条目"兜底（〔A〕guide_mod_v128
§2.7）。

**→ hexhammer**：单局 2~3 小时 + 存档分段（06 §1），存档窗口比 WC4 的常年账号短得多，
风险量级小；但**局内持久**的对象（将领等级/装备、主城特化）在版本更替时同样面对
"已获得的东西怎么办"。两条便宜的习惯：① 新档位只**追加在链尾**（或保证数值 ≥ 旧总量）；
② 删内容时先想"旧存档引用它会发生什么"。写进将来的存档格式 ADR 即可（候选，非急件）。

### 2.3 加载期校验缺失：Type 固定表越界闪退（→ docs/05 反模式清单）

**WC4 事实**：科技 Type 按 `Type×0x18` 索引引擎内 58 槽固定表，**无越界检查**——
mod 填 Type 58 起步直接启动闪退（SIGSEGV）；勋章家族同理，Type 23-39 共 17 槽全部
被官方占满，**无法新增独立家族，只能家族整体替换**（〔A〕guide_mod_v128 §2.7 / §2.8.1；
MOD_CHANGES §7）。

**→ hexhammer**：这是 docs/05 反模式清单第 4 条（"顺手加的字段没有第二个用例"）的
引擎侧镜像——**固定容量枚举表会勒死内容增长**，且炸法是最差的一种（加载期崩溃、
无报错信息）。本项目 .tres + 注册表（05 门 1/2）没有此问题，**要守住的红线**是：
任何"按枚举索引的数组/表"（克制矩阵、修正槽、AI 行为表）都必须动态容量或加载期
校验出 `assert`/日志，而不是静默越界。可作为 05 反模式清单的候选补充（待拍板）。

### 2.4 面板显示 = 裸值 + 聚合

**WC4 事实**：单位面板显示值 = 裸值 + HQ 科技加成（精锐步兵 475/21 = 325/12 +
T2 Lv7 150 + T7 Lv2 9），显示与裸值天然不同步（〔A〕guide_mod_v128 §2.8）。

**→ hexhammer**：docs/07 §2 的"锚点校验三层口径"（静态/掷骰/确定性推演）已经是
同类自觉。补充一条 UI 纪律候选：**面板显示的永远是聚合值时，调试工具必须能一键
展开"裸值 + 各来源贡献"**——WC4 的 475=325+150+9 分解是我们逆向时最贵的成本之一，
本项目从第一天就把分解视图做进调试面板，可省掉未来的整类排查。

## 3. 经济（指向 docs/06 §6）

### 3.1 收入乘数放关卡数据里 = AI 难度旋钮

**WC4 事实**：国家税率是**军团级每回合城市收入乘数**，作为字段存在 .btl 关卡数据内
〔B——WC4 项目方给定；仓库佐证：〔A〕`wc4-tools:docs/BTL格式规范.md` 记载军团记录
内含国家税率/血率（float32，行 100/109）〕；
AI 征服科技另走 CountryTechSettings 一套表，与玩家科技完全分离（〔A〕guide_mod_v128
§2.7"科技为玩家专属养成，AI 征服科技走另一套"）。

**→ hexhammer**：docs/06 §8 要求 AI 与玩家"同一套**意图系统**"——那是战斗规则对称；
**经济不对称是另一个自由度**，WC4 把它做成数据旋钮（收入乘数 + 独立 AI 科技/权重表）
而非代码分支。对本项目的直接映射：AI 难度 = 地图/剧本数据里的"每势力收入乘数 +
AI 造兵权重表"，规则层零改动。这正好落在 docs/06 待细化 #9（开局配置）与 #4（设施表）
的延长线上——建议经济数据模型从一开始就带 per-faction 收入乘数字段（待拍板）。

### 3.2 数值冗余度：×10 仍可玩

**WC4 事实**：我方 mod 将活动产出整体 ×10（贸易 ×10、奖池 ×10、勋带 ×8、碎片成本 ÷10）
后游戏仍然成立、节奏不崩〔B——WC4 项目方给定；改动清单见〔A〕`wc4-tools:docs/MOD_CHANGES.md`
§2~§5〕。

**→ hexhammer**：商业 SLG 的经济数值有**一个数量级以上的冗余度**——产出翻 10 倍
不会破坏可玩性，因为消耗端（造兵/升级）是弹性的。对本项目的校准含义（06 待细化 #4
设施收入）：**首发不必精调收入绝对值，优先定"收入:兵种成本"的比值锚**（如刀盾 100 =
N 回合收入）；比值锚定了，绝对值可以整档平移。这与 docs/08 §4 用"刀盾=100"做成本
基准的既有做法一致，推广到收入侧即可。

### 3.3 门槛+奖励组合拳与回收渠道（运营手法，选择性借鉴）

**WC4 事实**：1.30.2 同一版内：周期奖池 30→75（×2.5，305 条）+ 演习首通 ×2（334 条）
的大加强，与 183 个活动 NeedHQLv 0→10/20/30/40 分档的准入收紧**同时发生**——
"奖励加倍 + 门槛抬高"的防小号组合拳；同时 38 名新将在售回收 55,070 勋章（通胀对冲）
（〔A〕`wc4-tools:docs/UPDATE_1.30.2.md` §④/§5-1、`.../C_economy.md` §3.1/§5）。

**→ hexhammer**：单机无 live-ops，手法本身不直接迁移；可迁移的是**结构**：
① 难度分层用"准入门槛"而非"暗改数值"（将来的难度选项 = 地图/规则门槛，可展示、
可复现）；② 经济要有**回收渠道**（本项目已有：将领复活"足够回合数+大成本"、装备
购买——00 支柱 3），新增产出时同步检查回收端是否吃得下。

## 4. 将领·勋章·技能（指向 docs/06 §7）

### 4.1 显示名单一真值源：stringtable 陷阱

**WC4 事实**：勋章显示名走 stringtable 的 `general_medal_<Type>`（key=条目 Type，
家族再填 `Lv%d`）；JSON 的 Name 字段被 LoadMedals 解析存储但 **UI 从不读**——只改
JSON Name 在游戏里一个字都不变，曾直接导致一版 mod"改名失败"（〔A〕guide_mod_v128
§2.8.1，引擎 xref 定位）。另外 1.30.2 七语言 stringtable 只有繁中更新，其余六表陈旧
（〔A〕`.../E_platform.md` §2）。

**→ hexhammer**：docs/05 门 7（本地化：事件流即文案源）方向正确，WC4 是反面教材的
完整形态——**名字有两个来源、一个是死的**。对本项目的纪律候选：任何实体名（兵种/
装备/技能）只有一个权威来源（.tres 资源名或 key 表），UI 一律从它取；引入本地化层时
旧通道必须真死，不许"解析了但没人读"。

### 4.2 固定容量家族 = 扩展性反面教材

（事实已在 §2.3 引：勋章家族 17 槽全满，只能家族整体替换、付出"官方步兵迅捷勋带
不复存在"的代价，〔A〕guide_mod_v128 §2.8.1。）

**→ hexhammer**：装备/技能若做成"家族×等级"网格（06 §7 装备加属性或加技能、
待细化 #6 首发技能清单 5~8 个），等级维度可以固定（Lv1-5 足够），**家族维度必须可追加**
（动态列表）。WC4 的教训不是"别做家族"，而是"别把家族数焊死在引擎枚举里"。

### 4.3 商店排序 = 数据序 + Evaluate 分组

**WC4 事实**：商店列表**无排序代码**：显示顺序 = GeneralSettings 数组顺序（=加载序），
tab 按 Evaluate 分组（3→tab1 / 2→tab2 / 1→tab3 / 0 永不显示），再过滤已拥有
（〔A〕guide_mod_v128 §2.5；so 0x3083b0，`wc4-tools:analysis/report_so_offsets.md` §1）。

**→ hexhammer**：招募/商店 UI 的顺序应当**由数据显式拥有**（sequence 字段或排序键），
不靠"恰好数组这么排"。两个理由：① 测试可复现（UI 回归截图稳定）；② modding（05 门 6）
时玩家改数据即可控制商店，无需碰代码。WC4 的 Evaluate=0 隐藏也是一个好用模式：
**"不删条目、置 0 隐藏"**比删除更可逆——本项目将领/兵种的可用性标记可沿用（候选）。

### 4.4 独占档随晋升/成就发放（L7 模式）

**WC4 事实**：技能链顶级 L7 被整体改造为 `CostMedal=0`、**不可购买**，只能通过
将领晋升线或出厂自带获得（三个入口互证：晋升发放/晋升发放/随将出售）；旧付费终点
被摘出链表，中间新插付费档（〔A〕`.../A_generals.md` §3.2/§4.2）。

**→ hexhammer**：这是"RPG 感来自获取途径而非数值堆高"的成熟实现（00 支柱 3 的
精神）。对本项目将领技能（06 §7 待细化）的候选形态：普通技能商店/升级可得，
**每将 1 个"招牌技"绑定获取事件**（荣耀战记式挑战、晋升、阵亡复活后觉醒之类）——
独占性本身成为养成目标。仅作设计素材，待拍板。

## 5. AI 可设计性（指向 docs/06 §8）

### 5.1 AI 招募区间硬编码：玩家专属单位的正反两面

**WC4 事实**：AI 造兵是**按兵种大类掷骰**，区间硬编码（步 1-5 / 坦 6-10 / 炮 11-14 /
海 15-19 / 空 20-24 / 导弹 25-28 / 城防 35-38），权重表在 `assets/config/def_strategy.xml`；
精锐槽 100+ **不在任何掷骰区间内**——于是"兵种槽号 ≥124 时 AI 永不建造该兵种而玩家
可造"成为可依赖的设计事实〔B——WC4 项目方给定；〔A〕guide_mod_v128 §2.8 机制结论 +
`.../B_army_tech.md` §6-1"精英槽 100+ 本就不在 AI 城募掷骰内"，两版权重表未变〕。

**→ hexhammer**：两面都照收：
- **正面**：玩家专属单位（AI 永不造）是合法且便宜的设计自由度——本项目的"精锐棋子需
  主城特化"（06 §6）如果 AI 不做特化，天然形成"玩家有精锐、AI 只有普通"的难度缓冲，
  等价于 WC4 的精英槽机制，**不用写一行特殊代码**；
- **反面**：WC4 的可造集是**隐式**的（藏在引擎掷骰区间里），官方自己扩槽到 124 后
  旧断言"槽 >123 必崩"作废、行为边界漂移，逆向者踩坑（〔A〕B_army_tech §6-1）。
  本项目要把"AI 可造兵种表"做成**显式数据文件**（白名单 + 权重），而不是任何形式
  的隐式区间/魔法数——这也是 docs/06 §8"AI 走同一套意图系统"在经济侧的对应物。

### 5.2 Mob=0 被科技隐性拉起：零值身份单位 vs 全局平加

**WC4 事实**：Mobility=0 的兵种会被军团科技的机动**平加**隐性拉起（显示值=裸值+HQ
科技加成）（〔A〕guide_mod_v128 §2.8 机制结论）。

**→ hexhammer**：本项目有两个"零值身份"单位：医疗 ATK=0（无输出）、器械速度 2
（全场最慢）（docs/08 §3）。危险模式是**全局平加加成**：将来主城特化/装备若发
"全体 ATK+X""全体速度+X"，医疗会获得攻击、器械会提速，身份溶解。现有的
"精锐=四维×1.2"是**乘法**（0×1.2=0），天然安全。建议立一条数据纪律候选
（指向 06 待细化 #7 主城特化细则）：**全局成长走乘法或白名单，不走平加**；
确需平加时，零值身份单位列豁免表。

## 6. 官方平衡手法案例集（指向 docs/07 校准纪律 / docs/08 §5 工作流）

### 6.1 nerf 手段分类学（全部带前后值，〔A〕UPDATE_1.30.2 §④/§⑤）

| 手段 | WC4 案例（前 → 后） | 对本项目的启示 |
| --- | --- | --- |
| **改数值** | 纵深防御 L1-6：15/30/45/60/75/90 → 8/16/24/32/40/48（−47%）；洞察先机每格 −2%；纳米重塑 L4 −33% | 最便宜、最可逆。对应我们"改本文+改模拟器+改计算台"三同步（07 头部纪律） |
| **改门槛** | 183 个活动 NeedHQLv 0→10/20/30/40 分档；山口多闻 UnlockHQLv 1→16 | 强度不动、可达性动。对应难度分层用准入而非暗改数值（§3.3） |
| **改机制** | J36 战后增益翻转：攻击后自身 +30% 攻 2 回合 → **−10% 1 回合**（弹药消耗）；特性 129 L2 增益→惩罚 | 贵：WC4 需 feature×buff×stringtable **三表联动**才自洽。我们对应"机制改动=公式+模拟器+计算台+文案"四处同步 |
| **结构重排（隐性 nerf）** | 专属链扩级：不列颠雄鹰每级 −20%，新满级 L6=24 **仍低于旧满级 25**，且满级总价 2320→2500（花更多、效果更低） | 最阴险——账面"新增 L6 档"，实际净削弱。校准报告必须按"同价位对比"而非"档位存在性"汇报 |
| **对冲式重做** | J36 基础攻 ×3.2 + 自减益 + 机动 −1~−6：从"越打越强"改成"高爆发、打一炮亏一口、腿短" | 削弱保身份的范本：单维 nerf 会杀角色，多维对冲保角色。对应 08 各兵种"定位一句话"不动、数值带重锚的方法论 |
| **隐性通胀** | 38 新将回收 +55,070 勋章；免费轨勋章 −80% 而付费轨不动 | 产出调整必查回收端（§3.3） |
| **文案驱动的规则反转** | 刺刀冲锋等 23/24/25：数值两版相同，仅 stringtable"血量**小于**50%"→"**大于**50%"（残血反打窗口消失） | ⚠ 反面教材：规则行为变了，数据层零痕迹、只动文案——文档与数据脱节。本项目"文档即权威"（07 纪律）正是解药：**行为变更必须落在公式/常量里，不许只改文案** |

### 6.2 三条工作流结论

1. **数值优先于机制**：能用 −20% 解决的不动结构。机制改动（如血线反转、增益翻转）
   在 WC4 里牵动引擎+数据+文案三层，且玩家感知剧烈（23 名在售将受影响）。
   本项目 08 §6 待裁决清单的处置应遵循同一优先级：先试数值带重锚（08 §3.0 已有
   先例），机制层留作数值救不回时的手段。
2. **削弱必配补偿或身份保底**：J36 ×3.2、纵深防御"要塞→友军"泛化、荣耀装饰变实效
   ——官方每次 nerf 都在同版塞正向项。本项目校准（08 §5）若出现"某兵种必须弱"，
   学 J36：砍一维、补另一维、保持定位一句话不变。
3. **口径透明**：WC4 大量 nerf 藏在"新增档位/重排/文案"里，玩家社区要靠逆向才能
   还原真实变化。本项目有 07 三同步纪律与 08 校准报告传统，应保持"每次改动的
   前→后值全量留档"（本文引用的 WC4 案例能写成本文，正是那种留档的价值）。

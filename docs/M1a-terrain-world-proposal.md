这份方案把“生成完整地形世界”定义为可读、可走、可争夺、可复现的征服地图，而不只是增加噪声和贴图。建议保留现有六边形数学、分块与拾取基础，逐步补齐地貌过渡、水系、道路、聚落资源和生成验收；每一阶段都必须交付一个能独立运行的小场景，不要求一次重写。

## 问题与产品目标

### 当前基础与真正缺口

当前实现已有顶面、共享边带、三格角落，以及平地、一级坡和较大高差的连接；但连接面按归属格的单一材质绘制，没有把相邻地形的权重作为独立渲染数据。[当前地形构建器](https://github.com/jiezhou0319/hexhammer/blob/825f30a/addons/hexhammer/hex_terrain_builder.gd) 简单随机生成器使用高程和湿度噪声，分类为草、泥、岩、水、沙、林，并报告连通性；它没有生成河流、道路或城镇资源网络，也不会自动修复孤岛。[当前地图生成器](https://github.com/jiezhou0319/hexhammer/blob/825f30a/scripts/content/map_generator.gd)

“Catlike 很简陋”更准确地说是当前项目只落地了其中一部分：其教程还覆盖阶地、河流、道路、水体和多地形材质混合，不能把目前的能力边界当成 Catlike 方法本身的上限。[Catlike 教程目录](https://catlikecoding.com/unity/tutorials/hex-map/) 这些是 Unity 教程，应借鉴拓扑和三角化思路，而不是直接移植场景、Shader Graph 或渲染队列 API。[Catlike Terrain Textures](https://catlikecoding.com/unity/tutorials/hex-map/part-14/)

项目愿景是个人可完成的单机 PvE、持久大地图征服和 RTwP；因此地形的业务价值应服务“识别路线、争夺节点、做位置决策”，而不是模拟真实地球。[项目愿景](https://github.com/jiezhou0319/hexhammer/blob/825f30a/docs/00-vision.md) 现有路线图把正式生成器和地形数值修正放在 M3，M1b 的地形移动修正仍为零；本方案是新提案，不自动改写这些已定范围。[现行路线图](https://github.com/jiezhou0319/hexhammer/blob/825f30a/docs/03-roadmap.md)

### 业务目标

- **一眼可读**：玩家能区分主要地形、岸线、河道、道路和可通行路线；过渡更自然，但格子中心仍保持足够辨识度。
- **存在位置选择**：桥、山口、河谷、道路与资源点形成可解释的推进方向；不是无意义地把更多障碍铺满地图。
- **开图即可用**：在约定的地图档位和模板内，生成结果满足出生、资源和可达性约束，失败会明确解释，而不是让玩家反复盲试 seed。
- **内容可持续扩展**：新增生物群系、装饰或贴图不改变逻辑地形和随机结果；人工修改能锁定局部，不必整图推倒。
- **风险可控**：每次迭代都能回到旧渲染或固定地图；表现升级不改变尚未拍板的移动费、伤害与视野规则。

### 非目标

- **真实地球模拟**：不做板块运动、真实流体、全年气候、动态侵蚀或无限星球。
- **无限开放世界**：首个目标仍是有限六边形征服地图；大世界流式加载待实际规模需要再议。
- **完整建造游戏**：道路先作为生成的世界设施，不顺带引入玩家修路、收费和维修经济。
- **自动扩张战斗规则**：不在美术提交中偷偷改变移动费、冲锋、伤害、LOS 或视野。
- **一次集齐全部地貌**：首版“完整”指一个明确的温带世界模板能覆盖山地、平原、林地、岸线、水系、道路与聚落；雪原、沼泽和沙漠模板后续增量添加。

## 用户故事与世界描述

### 用户故事

- **玩家识图**：作为准备下令的玩家，我希望从策略视角区分森林、山地、河流与道路，从而理解为什么某条路线值得争夺。
- **玩家推进**：作为征服者，我希望出生附近有可用空间和基本资源，并有合理路线抵达目标，而不是开局被生成器困在孤岛。
- **内容创作者**：作为地图作者，我希望指定一条主河、一处山口和几个聚落后生成其余区域，且重新生成不覆盖我锁定的设计。
- **调试者**：作为发现坏图的开发者，我希望凭 seed、配置与版本复现问题，并看见具体失败的资源点或连通边。
- **换美术者**：作为调整画面的作者，我希望换纹理或改变过渡宽度时，地图拓扑、道路连接和可达性结果不变。

### 最终标准地图的业务描述

建议首个模板叫“温带河谷征服图”。地图包含一片主要陆地、可选择的海岸、连贯的低地与山脊、一条主河及少量支流、至少一个可控过河点、三组出生候选区、分布在合理距离内的核心资源，以及连接聚落的道路骨架。这里的“三组”是对现有 1 玩家 + 2 AI 设计的适配提案，不是生成器已经拥有的能力。

世界描述应写成“地理骨架 + 可玩约束 + 视觉风格”，而不是只有噪声频率。以下是配置草案，不是已实现的 schema；所有数值都是候选范围，必须通过批量生成与试玩校准。

```yaml
template_id: temperate_river_valley
schema_version: 2
generator_version: world_v1
seed: 7301
dimensions: {width: 60, height: 40}
geography:
  land_fraction_range: [0.70, 0.85]
  major_land_components: 1
  mountain_fraction_range: [0.10, 0.20]
  forest_fraction_of_land_range: [0.15, 0.30]
  elevation_levels: 6
hydrology:
  main_river_count: 1
  tributary_count_range: [0, 2]
  required_outlet: sea_or_declared_lake
  river_topology: cell_centered
  max_outgoing_links_per_cell: 1
  confluences_enabled: false
infrastructure:
  connect_required_settlements: true
  add_optional_road_loops: true
  guarantee_crossing_if_objectives_need_it: true
scenario:
  faction_count: 3
  spawn_footprint: center_plus_six_neighbors
  symmetry_profile: balanced_reference
  resource_profile_id: placeholder_before_M2
presentation:
  blend_profile: narrow_edge_soft
  landform_profile: slope_with_optional_terraces
  decoration_seed_channel: independent
rules:
  terrain_effects_enabled: false
```

约束之间冲突时应失败并给出原因，例如“要求三座聚落都相通，但强制河流隔离且禁桥”。不能通过无限重试、悄悄删河或把山区全部压平来伪造达标；模板中的目标数量、比例、资源预算和美术外观应分开管理。

## 成功指标与验收口径

### 北极星与测量原则

北极星建议采用**合格世界交付率**：固定 seed 集中，在有限尝试次数内生成并通过全部硬约束的请求数 / 总生成请求数。分母必须包括失败、超时与配置冲突；另报“第一次生成合格率”，避免靠重试掩盖生成质量。

下表都是本项目的建议验收目标，**不是行业标准，也不是现有实测成绩**。T0 先采基线；没有数据的性能、识图和公平性基线标为“待测”，以后按模板、尺寸、构建与设备分组，不把不同地图的平均值混在一起。开发者负责自动指标，主创负责目标取舍；同一个人可以兼任。

| 指标 | 业务意义与计算方法 | 建议目标 | 对应阶段 |
|---|---|---|---|
| 合格世界交付率 | 最多 4 次尝试内通过全部硬约束 / 请求总数 | 发布固定 seed 银行 100/100；探索性新 seed ≥95%，失败必须可解释 | T5 |
| 首次生成合格率 | 不重试也合格 / 请求总数 | 初始目标 ≥90%，同时记录修复和重试次数 | T5 |
| 必需目标可达率 | 从指定出生点能到达的必需城/资源点 / 所有要求的出生点-目标组合 | 100%；用实际启用的移动策略验证 | T5/T6 |
| 出生区有效率 | 出生中心与 6 邻格均界内、可通行、允许落兵，且无非法设施重叠 / 出生区总数 | 100%；原设计允许的后续特例必须显式列出 | T5 |
| 关键连通违规数 | 孤立必需目标、单向道路、无桥跨越禁渡河段等硬错误数 | 0；无关装饰岛可存在，不强求所有陆地一片 | T4/T5 |
| 水系合法率 | 有出口、无环、流向符合水面高程约束的 river reach / 总 reach | 100%；海/湖出口由数据声明，不要求全部入海 | T3/T5 |
| 地形识别正确率 | 约定相机与缩放下，受试者判断格子主地形/岸线/道路的正确数 / 样本数 | 候选 ≥90%；先 5 名试用者各 20 样本，样本不足就标探索结果 | T1/T4 |
| 决策点覆盖率 | 模板要求的桥/山口/道路绕行等决策区实际实现数 / 要求数 | 100%；温带模板先要求 2 个可解释决策区，不靠铺障碍凑数 | T5/T6 |
| 参考公平性偏差 | 平衡参考模板下，各出生点到最早期必需资源的最短成本差：`max/min - 1` | 候选 ≤25%；各资源分别测，零距离或不可达直接判配置错误 | T5 |
| 确定性复现率 | 同配置、seed、生成器和固定引擎构建下，世界逻辑摘要一致次数 / 重跑次数 | 100%；每个发布 seed 重跑 3 次 | 全程 |

公平性只对 `balanced_reference` 模板生效。真实 PvE 剧本可以不对称，但应把差异写进 `difficulty_profile`，不能在不说明的情况下让某一方因为地理生成获得巨大优势。

### 技术护栏

建议先以 60×40、1920×1080、约定相机档位、30 个测试棋子作为候选性能基准，确定目标硬件与 Godot 渲染器后再冻结指标。以下仅为启动预算：稳定运行阶段 p95 帧时间 ≤16.7 ms、p99 ≤33.3 ms；中图从点击生成到可操作 p95 ≤3 s；高亮/选择反馈 p95 ≤100 ms；不得把软件渲染探针的速度当作真实 GPU 成绩。

- **几何护栏**：固定压力场景中，裂缝、反面丢失、非有限顶点、重复面和可见 z-fighting 均为零；模型数据的几何 epsilon 按 hex_size 定义，并另做像素检查。
- **拓扑护栏**：道路双向一致、河流出流唯一、边与角只有一个稳定拥有者、装饰不进入地形拾取层。
- **资源护栏**：入库的场景、资源和测试不依赖被 ignore 的作者机文件；全新 clone 能导入并完成全部必需检查。
- **统计护栏**：必须报告失败 seed、修复次数、尝试次数、指标分布和超时；不能只输出最后一张成功图。

小图 40×30、中图 60×40、大图 100×60 是建议分组；先达标中图，再扩大覆盖。大图若尚未达到预算就标为实验，不借中图结果宣称全尺寸合格。

## 核心设计与数据边界

### 世界事实、游戏规则、表现三层分离

世界事实描述“是什么、在哪里、如何连接”；规则回答“某兵种能否穿越、要多少费用”；表现决定“怎么画、何种过渡、如何装饰”。三层不能互相代替，尤其不能从颜色、shader 或河水碰撞反推通行性。

```text
WorldConfig + seed + designer_constraints
                 |
          WorldGenerator stages
                 |
   WorldData: cells + links + waterbodies + POIs
           /                  \
  TraversalPolicy          Geometry/Style builders
  path/connectivity        terrain/water/road/features
           \                  /
       ValidationReport + scenario preview
```

建议将现有 `MapData` 保持为兼容的核心格子数据，在其旁边建立 `WorldData` 容器与查询接口，不立即把河流、道路、资源和气候塞进通用 `mods`。等 schema 稳定再通过明确版本迁移整合；旧地图缺失的新字段默认为“无河、无路、无 POI”，而不是加载时重新随机生成。

| 数据 | 内容与约束 | 首次需要 |
|---|---|---|
| `CellData` / 现有 `MapData` | cell_id、axial、逻辑高程、地形类型、通行基础字段；尺寸不可任意改写 | 已有基础 |
| `WorldFields` | 连续生成高程、湿度、温度、生态区；与离散游戏高程分开，配置与输出可诊断 | T5 |
| `NeighborLinkData` | 相邻格之间的稳定 link_id=`(min(cell_id),max(cell_id))`；道路为无向，river flow 另存 from/to | T2/T3 |
| `RiverReachData` | incoming 列表、最多一个 outgoing、流量等级、河床/水面锚点、所属水系；预留汇流而不提前开放 | T3 |
| `WaterBodyData` | 海/湖类型、水面标高、成员格、入/出水口、合法终点声明 | T3 |
| `RoadData` | 道路图、路线段、等级和聚落连接；不直接保存兵种移动费 | T4 |
| `CrossingData` | 桥/渡口锚点、连接哪两侧陆路、依赖哪段河道、实际可穿越边；初版只做桥 | T4 |
| `POIData` | 聚落、出生候选区、资源点、预留 footprint 和目标角色；资源经济数值由 M2 决定 | T5 |
| `WorldMeta` | seed、生成器/规则/schema/引擎构建版本、配置摘要、逻辑摘要、尝试与修复记录 | T0/T5 |

### 河流坐标约定必须先选定

建议首版沿用 Catlike 的**河流穿过格子、从一格流入邻格**约定，便于增量扩展现有顶面与连接带。其原始河流章节也采用穿格河道，并指出边界带已被坡/崖占用；基础版本不支持分流与汇流。[Catlike Rivers](https://catlikecoding.com/unity/tutorials/hex-map/part-6/)

这里的 `river link` 表示“河水从 A 穿过共享边流入 B”，**不是河流沿 A/B 的格边延伸**。道路也是格中心网络，因此“同一个 link 上有河和路”不能直接推导“这里需要桥”：那可能是顺河方向的重叠，而非横切河道。

- **桥的定义**：道路折线从一侧河岸进入、横切河道后到达另一侧；桥对象记录两岸和覆盖水域，不能以两条网络共享 link_id 代替相交检测。
- **禁用的组合**：初版禁止道路纵向覆盖河槽；路线改走岸边或重新寻路。河流与道路交叉只允许通过专门 crossing 模板解决。
- **扩展点**：首版最多 1 入 1 出；数据允许 incoming 列表，第二版开启 2 入 1 出和对应三叉河口几何。出流仍最多 1，不做河流分叉与三角洲。
- **玩法查询**：穿河或桥梁的可达边由 `TraversalPolicy` 与 `CrossingData` 判断；渲染河道不能直接将整个河流格设为水体禁行。

如果主创更看重“河流天然作为两格之间的边界”，可以另选格边河流，但必须补稳定顶点/角图和排水映射。这应是一个明确 ADR；不建议同一地图混用两种河流语义。

### 地形过渡分成四种，不只做模糊

- **材质过渡**：草-泥-沙-林地在共享边做两地形权重混合，在三格角落最多混合三种；中心主地形保持纯度，避免一张地图全变成泥色。
- **地貌过渡**：平地、斜坡、阶地、崖壁各有明确几何；只有一级高差允许阶地候选，较大高差保留清晰岩壁，不把所有山地抹平。
- **水陆过渡**：海/湖水面、河槽、水岸、入湖/入海口是独立连接类型；水位不是普通地形颜色。
- **生态过渡**：森林边缘的植被密度、湿地边的材质与地物逐步改变；它是装饰和生态标签，不自动改变规则地形。

材质混合可参考 Catlike 的“每三角形最多三种地形索引 + RGB 权重”，边混两种、角混三种；纹理版本使用 texture array 的思路，但在 Godot 上先做最小兼容性验证。[Catlike Terrain Textures](https://catlikecoding.com/unity/tutorials/hex-map/part-14/) 阶地必须同时解决边和三格角的组合，不能只细分边带，否则 slope-cliff 等角落会断裂。[Catlike Elevation and Terraces](https://catlikecoding.com/unity/tutorials/hex-map/part-3/)

## 渲染、拾取与更新方案

### 保留已有基础，拆开新增职责

建议逐步把单一 builder 拆成 `TerrainGeometryBuilder`、`WaterGeometryBuilder`、`RoadGeometryBuilder` 与 `FeaturePlacer`。现有 raw 顶点、渲染索引、碰撞汤、face→cell 表已形成重要合同，新三角形继续显式记录 owner、kind 和候选格，不能等视觉复杂后再补归属。

- **地形层**：持有可拾取的地表和河床几何，拓扑 owner 稳定；坡、崖、阶地和角落由同一规则派生。
- **水层**：独立水面/河流/岸线/河口 mesh；初版不参加地形 raycast，点击水面后的逻辑结果由水格或河床归属合同决定。
- **道路层**：道路、桥和交叉口单独批量 mesh；桥面若作为可站立表面，必须明确拾取优先级及其与逻辑格的对应。
- **地物层**：树、岩石和建筑避开道路、河床、桥端与单位锚点；不因装饰影响逻辑摘要或截获鼠标。
- **高亮层**：新增 `CellSurfaceSampler` 返回当前几何的高度与安全锚点；不能继续假定所有格顶面都是 `elevation * step` 的完整平六边形。

### 材质升级的最小安全路径

先做色板权重混合，再加贴图。当前每类地形单材质的 surface 组织可以保留作 fallback，但 transition 模式需要统一的共享 shader 或独立 transition surface，不能仍把整条边带强制画成 owner 格材质。

三角形的三个地形 ID 应在三顶点保持一致，避免整数 ID 被插值成不存在的地形；只有混合权重插值，并满足有限、非负且和为 1。具体将 ID 和权重放入哪个 Godot mesh 自定义通道，要在 Compatibility 和目标 Forward+ 都做 spike 后冻结；不把 Unity 的“第三套 UV”当成 Godot 已验证接口。

建议草/泥/沙采用软边，林地靠密度和地表混合，岩壁保留硬轮廓。崖壁改用侧面 UV 或三平面采样作为后续优化，避免把水平 XZ 纹理强行拉到垂直壁上；Catlike 的纹理章节也指出水平投影在陡面有拉伸问题。[Catlike Terrain Textures](https://catlikecoding.com/unity/tutorials/hex-map/part-14/)

### 跨 chunk 与增量更新

共享边由稳定最小 ID 拥有，角落采用稳定的角 key；河段与桥端锚点应从世界数据计算，不让两个 chunk 分别随机生成。改一格时默认重建其所在 chunk 和受影响的相邻 chunk，再按桥/河网络依赖扩展，不能把“一个 chunk 的边缘”误当成地图边缘。

材质、贴图和纯装饰变化原则上不重建碰撞。高程、河床、阶地和桥面变化必须重建相关几何与 face 表，并让高亮位置失效；若初版无法安全做增量更新，允许明确的“整图重建按钮”，不要伪装成支持局部编辑。

## 世界生成管线

建议先手工固定图再程序生成：先把每种连接画对、规则解释清楚，再让生成器批量组合。Red Blob 的地图生成项目强调先提供山、谷、海等设计控制，再派生水循环、河流和生态，这可作为“约束驱动生成”参考，但它是 Delaunay/Voronoi 项目，不是可直接复制的六边形实现。[Red Blob Mapgen4](https://www.redblobgames.com/maps/mapgen4/)

| 阶段 | 输入与输出 | 应记录的诊断 |
|---|---|---|
| 配置校验 | 校验范围、预算、互斥选项、锁定约束与能力开关 | 所有冲突原因；不产半图 |
| 地理骨架 | 模板/锁定区 → 陆海、山脊、低地与连续高程 | 陆地比例、山地比例、主要区域数量 |
| 地貌整形 | 平滑局部极差、识别山口和谷地，量化游戏高程 | 修改量；锁定区不得被覆盖 |
| 排水骨架 | 连续高程/指定水体 → 每格 downstream 或合法 sink | 出口、无环、盆地与洼地处理 |
| 流量与水系 | 汇水量超过阈值 → 主河/支流/湖/河口 | 流量、河宽、河段、终点、非法落差 |
| 气候与生态 | 纬度/高程/水系距离/湿度 → biome 与植被密度 | 生态比例、孤立小斑块、河谷湿润带 |
| 聚落与资源 | 可通行安全区 + 地理骨架 → POI 与出生区 | footprint 冲突、资源预算与距离 |
| 道路与过河点 | 必需聚落连接 → 路线、桥、必要备选道路 | 连通、绕行、桥端与关键瓶颈 |
| 可玩校验与有限修复 | `TraversalPolicy` → 合格世界或明确失败 | 修复、重试、失败 seed、指标总表 |
| 表现派生 | 世界事实 + 独立美术 seed → mesh/地物/摘要 | 构建预算与渲染证据 |

### 水系的可执行合同

首版手工指定源头与出口，生成版再引入汇水。排水必须形成无环、有终点的有向网络；同高程平台用稳定排序或排水 rank 消除循环，洼地只能被声明为湖、被受限填洼/开槽，或返回失败，不能绕着平台随机走到死循环。

连续高程用于生成，离散高程用于游戏，但**量化后必须重验水面单调性和河床容纳**。若低分辨率量化造成“河水上坡”，应局部挖槽或拒绝该路线；不能只在 raw 高程上验证成功就画到另一套高程上。

水面深度、流速、宽度、河床下切和瀑布是表现参数，不是物理模拟。共享连接上的水面锚点必须完全一致；同一湖体水位一致，湖出口不高于允许的溢流口，海岸、河口和瀑布有独立连接模板。Catlike 的 Water 章节区分 open water、shore 和 estuary，也说明水位一致性需要管理，不会自动替业务保证。[Catlike Water and Estuaries](https://catlikecoding.com/unity/tutorials/hex-map/part-8/)

### 道路与聚落的可执行合同

道路先连接实际聚落，而不是随机画线。建议候选聚落对先计算合法路径成本，再取最小连接骨架，必要时增加少量回路；路径权重表达绕山、绕水和建设偏好，不直接等于兵种的移动费。

若唯一聚落连接需要过河，先寻找合法桥址并创建 crossing，再计算最终道路；否则明确失败或放弃该候选聚落。增加道路后重新验证出生区 footprint、桥端和所有必需目标可达性，不能只证明“道路自己的图是连通的”。

### 随机性与人工约束

建议以 root seed 派生具名随机通道：`geography`、`hydrology`、`biome`、`poi`、`roads`、`decoration`。新增一棵树不应消耗前面阶段的 RNG 并改变河流；同一阶段内部固定遍历序、并列规则和排序口径，不能依赖运行时 hash 顺序。

人工约束分成 `locked` 与 `preferred`：强制主河/出生/城址不能被修复步骤覆盖，偏好可放宽但要记录。后续锁定编辑能力完成前，先用固定 JSON/Resource 模板承载约束，不为第一版搭建完整地图编辑器。

## 渐进交付路线

路线按依赖排序，不承诺未经基线测量的日历工期。T0/T1 可以作为地形侧短切片；T2 以后是扩展提案，T5 是完整世界生成里程碑，T6 是与现行 M3 规则定稿衔接的入口，不应阻塞 M1b 的平地 RTwP 内核证伪。

| 阶段 | 独立可见交付 | 依赖 | 本阶段 Must / Should / Could | 停止条件 |
|---|---|---|---|---|
| T0 验收底座 | 旧沙盒在干净 clone 上可读可选；统一入口产出证据 | 修复复核 | Must：可靠门禁与渲染证据；Should：目标硬件基线 | 不能复现绿灯则不扩大生成复杂度 |
| T1 材质过渡 | 一个 7 格测试场中草-泥-岩不再硬切，中心仍可辨认 | T0 | Must：两格/三格权重；Should：纹理版；Could：噪声边界 | 比旧版更难识图则缩窄过渡 |
| T2 地貌升级 | 固定小图具有坡、阶地、崖壁和闭合角落 | T1 数据合同 | Must：连接矩阵；Should：阶地；Could：崖壁三平面纹理 | 接缝/归属失败则退回简单坡 |
| T3 水系切片 | 手工主河经过斜坡，接入湖/海，有连续岸线 | T2 | Must：单河/水位/河床/出口；Should：瀑布；Could：支流汇入 | 单河未稳定前不做自动河网 |
| T4 道路与桥 | 两聚落道路横切主河，有可读桥与合法端点 | T3 | Must：道路骨架/桥；Should：路口/回路；Could：道路等级 | 无合法桥址须明确失败 |
| T5 完整世界生成 | 一键生成温带征服图，附出生、资源、路网、河网与诊断 | T3/T4 + 场景约束 | Must：阶段化生成/可玩校验；Should：有限修复；Could：更多模板 | 必需目标不可达则不交付给玩家 |
| T6 规则与内容深化 | 地貌影响路线选择且效果可解释；增加生态与装饰 | M3 地形规则拍板 | Must：规则/路径/预览一致；Should：生态密度/汇流；Could：雪原/沙漠 | 规则尚未定稿时仅开放视觉模式 |

## 门禁矩阵与报告格式

### 门禁不仅计数测试，还要证明世界可交付

| 门禁 | 覆盖 | 自动化与人工要求 |
|---|---|---|
| 数据/拓扑 | schema、邻接、河流、道路、出口与 POI | 纯逻辑 headless；非法输入、空图、NaN、版本不符都拒绝 |
| 几何 | top/edge/corner/riverbed/shore/road/bridge | 非有限值、裂缝、绕序、face 表和 shared anchor 测试 |
| 引擎集成 | 拾取、异步选择、相机、setup 与编辑后重建 | 真实物理帧；不能只用软件射线代替 |
| 渲染 | 混合权重、可见性、岸线与深度顺序 | 固定小场景像素检查 + 目标渲染器截图；透明水效果不可只靠节点存在验收 |
| 世界有效性 | 出生、资源、河网、路网、目标可达 | 固定 seed 银行与随机探索分开；明确模板/规则版本 |
| 性能/识读 | 帧时间、输入延迟、读图正确率 | 目标硬件实测与小样本试用；不得由 headless 全绿推出 |

建议压力场景从很小的局部图开始：异材质两格、三地形角、坡-阶地-崖角、跨 chunk 河流、源/终点、河入湖、桥跨河、道路路口、出生旁资源。河流转弯与道路共存尤其需要按拓扑模板测试；Catlike 道路章节也单独处理河流附近道路位置，不能只把两套 mesh 叠在一起。[Catlike Combining Rivers and Roads](https://catlikecoding.com/unity/tutorials/hex-map/part-7/)

### 最小诊断输出

```text
WorldValidationReport
  config_id / seed / schema_version / generator_version / engine_build
  rules_profile / render_profile / target_device
  attempt_count / repair_count / first_pass_valid
  required_reachability / spawn_footprint_valid
  river_cycle_count / invalid_outlet_count / road_disconnect_count
  geography_distribution / resource_access_cost_by_spawn
  generation_ms_by_stage / build_ms / frame_p95_ms
  errors[{code, cell_ids, link_ids, constraint_id, explanation}]
  world_digest / fixed_screenshot_ids
```

建议错误码先包括 `NO_VALID_SPAWN`、`RESOURCE_UNREACHABLE`、`RIVER_CYCLE`、`NO_RIVER_OUTLET`、`BRIDGE_ENDPOINT_INVALID`、`ROAD_NETWORK_DISCONNECTED` 和 `LOCKED_CONSTRAINT_CONFLICT`。错误必须指向具体 cell/link/约束，而不是只有一个 `ok=false`。

提交级别先跑固定局部压力场景与少量 smoke seeds，完整 100-seed 检查按每个已支持的模板/尺寸独立统计，在定期回归与发布前执行。seed 银行应提前冻结或按固定采样规则生成，不能只留下已知好图；确定性重跑与随机探索各自报告，实验档位未达标时不混入“全部支持档位通过”的结论。

## 与现有里程碑的衔接

建议现在只采纳 T0/T1 的实施优先级，并冻结 T2/T3 的数据合同，不立即扩大 M1b 的战斗规则。T3/T4 可在独立地形沙盒逐步试验，T5 正式生成放在 M3 或一个明确新增地形里程碑；主创需要先决定是否为此调整现行路线图。[当前阶段划分](https://github.com/jiezhou0319/hexhammer/blob/825f30a/docs/03-roadmap.md)

M2 的资源与城生产定义没定稿前，T5 用 `POI role` 和占位资源预算验证地图结构，不编造正式产出或成本。M3 的河流/坡地/道路效果没拍板前，T6 关闭；视觉上可出现河和路，但沙盒必须明确标注“地形效果未启用”，避免玩家从画面推断不存在的战斗规则。

### 需要主创确认的决策

- **河流拓扑，阻塞 T3**：是否接受首版穿格河流、1 入 1 出；建议接受，汇流作为数据可扩展项后续开启。
- **视觉风格，阻塞 T2 深化**：偏阶地棋盘感还是平滑坡；建议坡为默认、阶地为 style 开关，崖轮廓保持清晰。
- **首个世界模板，阻塞 T5**：是否以温带河谷、三组出生候选区作为参考；建议先固定一个模板，不同时造五种气候。
- **地形玩法，阻塞 T6 而非 T1**：河流禁渡/可涉、桥作用、道路成本与坡地限制；沿用 M3 决策门，不默认加入补给或天气系统。
- **目标硬件与渲染器，阻塞性能验收**：主创指定最低设备、分辨率和 Forward+/Compatibility 支持范围，再冻结预算。
- **排期取舍，阻塞扩大范围**：若完整地形世界前移，应明确哪些现有功能后移，而不是保留全部承诺并叠加工作。

## 推荐起点

先交付“一个 7 格、三种地形、两档高程、跨 chunk 的过渡测试场”，把权重、索引、拾取与截图门跑通。然后只加“一条有源有出口的河”，再加“连接两聚落并横切该河的道路与桥”；三张手工图稳定后，才让生成器自动拼出世界。

这样的递进顺序让每一步都有可见收益和独立退路：旧基础不丢、规则不被暗改、失败能定位。完整世界的标准也从“看起来东西很多”，变成“每一张交付的图都满足可读、可达、有决策、能复现的明确合同”。

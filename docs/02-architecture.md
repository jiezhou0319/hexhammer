## 1. 分层总图

```
┌─────────────────────────────────────────────────────┐
│ 表现层  scripts/ui  + scenes                         │
│   渲染 / 相机 / 输入 / HUD —— 只发命令、只听事件      │
├─────────────────────────────────────────────────────┤
│ 命令层  scripts/core/command                         │
│   Move/Attack/Retreat/Cast…（玩家、AI 共用同一       │
│   入口，携带脉冲时戳——ADR-12）                       │
├─────────────────────────────────────────────────────┤
│ 引擎层  scripts/core/battle_engine + clock           │
│   校验 → 执行 → 产出事件流 → 推进脉冲（ADR-12）      │
├─────────────────────────────────────────────────────┤
│ 规则层  scripts/core/rules（纯函数）                  │
│   命中/致伤/豁免/士气 —— 无状态，可独立跑万次模拟     │
├─────────────────────────────────────────────────────┤
│ 领域层  scripts/core/hex + state + data              │
│   六边形数学 / 战场快照 / .tres 数据模型              │
└─────────────────────────────────────────────────────┘
        依赖方向只能向下。UI 不知道引擎内部，引擎不知道 UI 存在。
```

> **2026-10-09 对账**：总图已按 ADR-12 更新——回合机、EndPhase、回放/网络出口
> 移出架构；分层原则（依赖只向下 / UI 只发命令听事件）不变。

**数据流（一次玩家操作）**：

```
鼠标点击 → InputController 组装 Command
  → BattleEngine.execute（校验+改 BattleState+产出事件）
  → 事件流（BattleEvent，ADR-7）+ 信号 state_changed/battle_over
  → Renderer.queue_redraw / HUD 更新
```

## 2. 决策记录

### ADR-1 六边形坐标系：axial (q,r) 存 `Vector2i`，pointy-top
- 备选：cube (x,y,z 三元组)、offset (col,row) 直接存
- 选 axial：距离/邻居/寻路全 O(1) 简洁；offset 仅在地图生成与显示时转换（`Hex.offset_to_axial`）
- 后果：所有代码禁止直接对坐标做算术游戏逻辑，必须走 `Hex` 静态函数——坐标变换 bug 集中在一个文件
- 佐证：godot-hexgrid、Wesnoth 同样以 axial/cube 为内部坐标

### ADR-2 逻辑层不继承 Node（RefCounted + 纯函数）
- 备选：一切皆 Node 场景树（Godot 直觉写法）
- 选纯逻辑：① headless 单测/批量模拟不需要场景树；② 战斗可以瞬间解算完（AI/回放），动画是事后呈现；③ 避免 Node 生命周期耦合状态
- 后果：引擎信号经 Godot `signal` 机制发（RefCounted 支持信号），View 直接 connect —— 已验证可行

### ADR-3 内容数据用 Godot Resource（.tres），不自定义格式
- 备选：JSON/YAML + 自写解析（Wesnoth WML 路线）
- 选 .tres：编辑器原生编辑+类型检查+嵌套引用；GDScript `preload` 类型安全
- 后果：modding 玩家门槛比 JSON 高——缓解：M3 提供"JSON → .tres 导入器"或迁移到 JSON（届时再看，数据模型类不变，只换序列化）

### ADR-4 命令模式作为唯一变更入口
- 所有 BattleState 变更必须经 `Command → BattleEngine.apply_*`，引擎外不允许直改 state（测试代码豁免）
- 这一个约定同时解决：AI 复用（产出命令即可）、回放（记录命令序列+RNG seed 重放）、悔棋（命令可逆化，M3）、异步网络（命令序列化传输）
  > **2026-10-09 注（评审 G4）**：随 ADR-12 收缩——回放=headless 内部工具、悔棋=读档（M2 存档）、
  > 异步网络出范围（00 v5 纯 PvE）；本条**仍成立的只有 AI 复用与 headless 确定性重放**。
- 后果：新增玩家操作 = 新命令类 + 引擎 apply 原语，两处小改

### ADR-5 骰子集中注入（BattleRNG + seed）
- 规则代码禁止散落 `randi()`；同 seed 同战局 → 回放/测试确定性（Tessera 同思路）
- 后果：~~多人热座无问题；真网络对战需 lockstep 命令+seed 同步（远期，接口已留）~~
  **2026-10-09 注（评审 G4）**：热座/网络对战均已随 00 v5 纯 PvE 出范围，本条后果作废存档；
  seed 确定性的现行消费者 = headless 自战、回归测试与 M2 存档续跑（ADR-12）。
- **AI 随机源归属（2026-10-09 补，评审 P2-10）**：随机合法 AI 的指令随机同样走
  BattleRNG 流、不另设种子源——保证 headless 同 seed 复现与快照续跑一致
  （T15/M2 存档的"RNG 内部状态"须涵盖全部消费方，含 AI）。

### ADR-6 特殊规则 = 数据挂载 + 效果注册表
- `SpecialRule.rule_id` → 引擎内效果表分发（现役首个示例 = **冲锋 tag**（06 §3.4，
  分发机制随 M1b-T5 战斗管线、tag 本体随 M1b-T7 落地）；~~现：frenzy/fear~~
  旧 spike 示例随清码作废——"恐惧类 debuff"属 M3 将领技能，2026-10-09 更正，评审 P2-3）
- 新规则= 新 .tres + 注册表一个 case，不改 UnitProfile/引擎主干
- 后果：规则间交互（如 冲锋 × 长枪迎击 的结算顺序）要在注册表内显式处理，防止隐式耦合——M2 若规则 >10 条，重构为小型 ECS（组件=规则实例）

### ADR-7 事件流尚未结构化（当前为 String 日志）—— M1 重构为事件对象
- 当前 `logged(text)` 只是给 HUD 看的字符串
- M1 起产出结构化 `BattleEvent`（RefCounted 子类：DiceRolled/WoundApplied/UnitFled…），
  日志文本、动画、音效、统计都从事件流派生——这是回放与表现解耦的关键一步
- **2026-10-07 注**：玩家回放已取消（纯 PvE、不做对战），事件流的消费端收缩为
  动画/日志/统计/调试；命令序列+seed 的确定性保留为 headless 自战与内部测试服务（ADR-5）
- **2026-10-09 增补（事件最小契约，随 M1b-T11 落地）**：公共信封五字段——`tick`
  （脉冲序号）/ `type`（事件类型）/ `faction_id` / `unit_id`（主体棋子）/ `payload`
  （类型专属字段：反击方、伤害值、触发原因等进 payload，不进信封）。首批事件类型以
  04 M1b-T11 六类为准（移动/攻击/反击/冲锋/士气变化/阵亡；~~过路费~~ 事件随体系
  移除删去，2026-10-09；上方
  DiceRolled/WoundApplied/UnitFled 为回合制时代示例，随零恢复重写作废）。向前兼容
  两条铁律：**消费端必须容忍未知 `type`**（M3 技能、M5 音效加事件不改旧消费端）；
  **公共字段只增不改语义**。事件流被 M1b（T13 报表）、M2（存档）、M3（终局摘要、
  事件→文案）、M5（音效）四方跨里程碑消费——契约在此定死，验收口径见 04 M1b-T11。

### ADR-10 ⛔【已废止 2026-10-06】棋子粒度：部队级（将 + 兵数）——2026-10-05 v2 变更
> **废止理由**：与 `docs/00-vision.md` v4 支柱 3"棋子即兵"冲突——一枚棋子即一个独立
> 作战单位，无带兵结构、无编制、无兵数条；`TroopType / RegimentState / Lord` 三件套作废。
> 以下全文仅存历史，粒度决策待按"棋子即兵"重写（连同 §5 处置表）。
> 当前无代码迁移成本：`scripts/`、`tests/` 已在 2026-10-06 删除。
- **背景**：玩家要大地图、多派系、大军团，且操作不因规模崩溃。
- **备选**：① 单模型大军（Wesnoth 式）——操作量随规模线性爆炸，80 棋子/回合的微操不可持续；
  ② 团级 WFB 原味（rank&file 摆模型）——规则量 4~5 倍且与"大规模"互相拖累；
  ③ **部队级（选中）**：棋子=Regiment（将领+兵种+兵数），参照三国志 11 / HOMM。
- **领域模型变更**：
  - `UnitProfile` → `TroopType`（兵种模板：攻/防/T/Ld/速度/克制/特技）
  - `UnitState` → `RegimentState`（兵种引用、兵数 current/max、将领槽、经验、士气状态）
  - 新增 `Lord`（将领：Profile 属性/技能/装备 + State 存活/俘虏/位置绑定）
  - 解算粒度：一次交战 = 攻防骰按兵数抽象（如 attack_dice = clamp(兵数/N, 1, M) + 将领加成），
    具体口径 M1-T2 定并进 autobattle 校准
- **后果**：现有 demo 的"一棋子=一模型"数据要迁移（见 §5 处置表）；战场规模上限由
  棋子数（≤~150）而非模型数决定，寻路/渲染/操作全部可控。

### ADR-11 交战自驱：接触自动开打，玩家不下"攻击"指令 ⛔【已并入 ADR-12（2026-10-07）】
> **废止说明**：方向（玩家不点"攻击"、交火自动跑完）由 ADR-12 继承；"每回合边界自动解算一轮"
> 的回合制表述随实时化改向作废，战斗时序见 docs/06 v0.5 §3。
> 以下全文仅存历史。
- **规则**：部队移动进入敌相邻格（或宣告冲锋）→ 进入交战状态；此后**每回合边界自动解算一轮**
  攻防（先手按冲锋/速度），直到一方崩溃/被歼；被远程射自动承受不还手（射程外），被近战
  攻击自动还击。玩家可下的命令：移动/冲锋/撤退/技能——没有"攻击"按钮。
- **理由**：这是"大规模不微操"的核心；三国志 11 与 Dominions 验证过的手感；
  同时让回合边界（已有显式回合机）成为唯一解算时点，杜绝状态不一致。
- **后果**：回合机在 faction 回合开始时触发"交战结算"步骤（排在移动前）；
  事件流（ADR-7）成为战斗呈现的唯一来源——自动解算的每颗骰子都要进事件流供 HUD/回放消费。

### ADR-12 时间与指令模型：全局脉冲时钟 + 随时暂停 + 棋子双充能轴（2026-10-07，随 00 v5 / 06 v0.5 定稿）
- **背景**：WeGo 规划-结算分离在两端承压——30 枚棋子的规划操作量、结算观看时长
  顶爆一局预算；主创要求钢4式操作逻辑（暂停指派、放行兑现），且三国志11 锚点
  的原生时间形态本就是实时+暂停。
- **备选**：① WeGo 规划-结算分离（废，2026-10-07 带案复议推翻）；② 纯连续 RTS
  （废——丢失确定性与六边战术的可读性）；③ 全局波次脉冲（满一条全体动一遍，
  废——主创裁决改为个体充能：每脉冲只有部分棋子在动，其余回费）。
- **选择**：全局脉冲时钟（1x 约 1~2 秒/脉冲、多档变速、随时暂停，单次行动结算原子
  不可断）；每棋子**移动费/攻击费双充能轴**（移动冻结攻轴、首攻半费、待机空转）；
  指令实时生效无锁定窗口；同脉冲行动按势力序（玩家先）→棋子 ID 序；
  经济按账期（每 N 脉冲）结算。
- **后果**：
  - 回合机、意图锁定、四姿态、事件回放（玩家侧）退出架构；ADR-11 并入本条；
  - **棋子运行态归属（2026-10-09 评审 C2 收口）**：一切持久可变状态显式落在 BattleState
    的棋子运行态（UnitState）上——位置 / HP / 双充能轴 / **反击率当前值**（10 §3 衰减恢复）/
    buff 与 tag 实例，禁止引擎外散置；M2 存档 = BattleState 全量快照（03 §M2-7）因此天然覆盖，
    headless 同 seed 重放亦据此对齐；
  - ADR-4 命令模式保留：命令=实时指令，携带脉冲时戳；ADR-4 的悔棋/回放分支收缩
    （悔棋=读档，回放=headless 内部工具）；
  - ADR-5 确定性保留且更纯粹：固定脉冲时钟+时戳指令+seed ⇒ headless 快进脉冲即可
    复现任意一局，自战模拟器与回归测试成本更低；
  - ADR-7 事件流保留但消费端收缩（动画/日志/统计/调试）；
  - AI 挂接点=脉冲间隙批处理（06 §8 分层节律），不占渲染帧，暂停时静止；
  - 渲染层从"回合快照"变为"连续时钟的动画插值"——第二代 UI 的技术底座变化最大，
    M1 切片的证伪对象即此内核。

### ADR-13 表现层 3D 化：3D 地形 + 3D 棋子 + 策略相机（2026-10-07）
- **背景**：主创明确要求棋子与模型均为 3D 表现（关键约束）；参照锚点三国志 11
  本就是"3D 地图 + 固定策略相机"的原生形态，与 WeGo→RTwP 改向后的连续时间表现互洽。
- **备选**：① 2D TileMapLayer 六边形瓦片（原 ADR-8 第二代方案，废）；② 3D 地形 +
  2D 立绘棋子混搭（视觉割裂、拾取两套坐标，废）；③ **全 3D（选）**。
- **选择**：Node3D 场景为底座——六边形地面网格（程序生成的**带高程连续网格**，
  见下方 2026-10-09 修订）、
  棋子为独立 3D 场景（模型 + AnimationPlayer + 朝向控制）、固定俯角策略相机
  （平移/缩放/边界钳制）。第一代 UI **即用 3D 原语**（胶囊/方块）验证，
  不走 2D 色块过渡。
- **后果**：
  - 核心架构零改动：逻辑层（ADR-2 纯 RefCounted）不感知渲染维度，
    "删 `scripts/ui/**` 后测试全绿"的验收口径不变；
  - 两个新 spike 风险项提前进 M1：**拾取链路**（屏幕射线 → 对地形 mesh 物理
    raycast → 世界坐标 → axial）与**策略相机控制器**
    （axial ↔ 世界坐标映射放 view 层辅助模块）；
  - 移动范围/路径高亮：第一代用"每格一个半透明高亮 mesh"（简单可靠），
    shader/贴花后期再议；
  - 资产管线成为真实工作流：GLTF 低模（素材库或 Blender 自产）+ 命名/比例/朝向
    约定，M3 前建立；
  - 渲染器维持 forward_plus；≤150 低模棋子的性能余量充足，LOD/实例化远期再说；
  - ADR-8 第二代 TileMapLayer 表述废止（分两代原则保留）；05 门8 同步更新。
- **2026-10-09 修订（M1a 拍板，P0-范围-1）**：地形地基升格为独立里程碑 M1a——
  ① **高程分层进核心**：数据模型（离散等级）+ 邻格高差生成**悬崖面/斜坡连续
  连接**（文明6 式无缝联动网格），新锚点：Civ6 地形形态；
  ② **拾取取消平地简化**：直接对地形 mesh 物理 raycast（原文"平地先用数学平面
  求交"作废）；
  ③ **美术并行验证分支**：材质槽体系（类型→材质映射，色块起步）+ 贴图试验分支
  （同接口即换即所见）——主线开发不含贴图、后合并；
  ④ 数值修正仅留数据层扩展位、不实现（07 地形修正仍待定，M3 落地）。

### ADR-14 河流拓扑：格边河流（2026-10-10，M1a+ 提案决策清单主创拍板）

- **背景**：M1a+ 提案（docs/M1a-terrain-world-proposal.md「河流坐标约定必须先选定」）
  给出两种河流语义：穿格河流（Catlike Part 6 口径——河水从一格流入邻格，河床
  落在共享边带上；提案建议项）与格边河流（河流天然是两格之间的边界实体）；提案
  明示"若主创更看重河流作为边界可另选格边，但必须补稳定顶点/角图和排水映射，
  且不建议同一地图混用两种语义"。
- **备选**：① 穿格河流（提案建议项，废）；② **格边河流（选）**。
- **选择**：河流 = 六边形**边**的实体——一条河 = 一串共享边的有序序列，两侧格
  互为河岸；与穿格语义不混用。
- **后果**：
  - T3 开工前须补两个前置（提案明示）：格边的**稳定边/角图**（edge key 沿用
    T4 归属规则先例：无向边 key = 两格 ID 排序）与**排水映射**（格边流向表，
    无环有终点）；
  - 数据合同草案 §5 RiverReachData / §8 CrossingData 原按穿格悬置起草——
    T3 转正时**按格边整体重议**（河段 = 边序列而非格序列；桥 = 跨格边河流的
    两侧陆路连接）；
  - 几何面：河流渲染与高程连接带**共享边几何**——T3 须解决共存与归属
    （Catlike Part 6/7 仅可借鉴拓扑思路，不移植其穿格几何）；
  - 玩法查询（禁渡/涉渡/桥）沿 M3 决策门，本 ADR 只定拓扑不定规则。
